# AGENTS.md

## Project

**BookNook** (`cat_ron`) — small online library app (discover, add, borrow, return books). Frontend + two API routes. Routes: home `/`, books list `/books`, book details `/books/[title]`, `/login`, `/register` (mock auth via localStorage); private (gated by `RequireAuth`, visible in navbar only when logged in): `/add-book`, `/my-books`, `/my-borrows`, `/my-profile` (accessed via the navbar avatar dropdown showing the user's **name, My Profile + Logout**; the profile card shows large circular avatar, serif name, email, "Member since" from `AuthUser.joinedAt` resolved per-account by email via a `booknook-members` registry in localStorage — stamped by `registerMember()` at **registration** (or first login for non-registered users) and permanent thereafter; an **Edit Profile** in-card form edits name + photo (≤1MB Data URL) via `AuthProvider.updateUser` — email is the identity and stays read-only); `logout()` clears the session **and always routes to `/`** (home) from any page; API `/api/books/latest` (MongoDB `find().sort({ addedAt: -1 }).limit(?limit, default 10)` via `src/lib/mongo.ts` + `MONGODB_URI` in `.env.local`; falls back to the mock catalog when no MongoDB is reachable) and `/api/books/detail?title=` (case-insensitive single-title lookup in the same collection). Homepage "New Arrivals" shows the latest **6** books (2 rows × 3 on desktop; `grid-cols-2` on mobile) fetched client-side (`src/components/home/LatestBooks.tsx`, `/api/books/latest?limit=6`); `/books` lists all 20 + user-added books from `src/lib/userBooks.ts`; borrows from `src/lib/borrows.ts`. The details page borrows through a modal (`Borrow "Title"` + read-only User Name/User Email inputs prefilled from the auth session, Confirm Borrow) — identity fields are never editable. `Book` carries details-page fields — `description`, `addedBy {name, email}`, `copies` (optional). The Add Book form (dark-green hero "Add a Book" + centered `#0a1d12` form section, matching the reference) captures Book Title/Author Name (2-col), Category + Total Copies (2-col), a **file-upload cover picker** (image ≤1MB read as Data URL, otherwise `FALLBACK_COVER`), Short Description, and read-only User Name/User Email prefilled from the session (stored as `addedBy` in localStorage), with a full-width "Add Book" button; details without a description get a synthesized per-book fallback; `FALLBACK_COVER` (exported from `src/lib/books.ts`) is applied via `onError` when covers 404. **The details page never renders a 404**: it resolves via local catalog → `/api/books/detail` → a synthesized per-title `Book` (FALLBACK_COVER, composed description, donor = signed-in user) — `notFound()` is not used on `/books/[title]`. Availability = `copies − active borrows of that title` (from `getUserBorrows()`); when `copiesLeft` reaches 0 the button shows "Not Available" (disabled, muted-green combinated, line-through) **for everyone including the borrower** — "Borrowed — yours for 7 days" shows only while the holder still has copies remaining. Register success ends the fresh session and redirects after ~1.1s to `/login` (spec: register → Login; `booknook-next` is left intact so the following login still lands on the remembered route).

## Commands

- `npm run build` — typecheck + production build
- `npm run lint` — ESLint (`eslint.config.mjs`)

There are no tests and no CI. Verify changes with `npm run build` and `npm run lint`.

## STRICT RULE — no test writes to production

Do **not** verify deployments or test features against the deployed app by creating throwaway accounts (e.g. `prodtest…@booknook.test`, `e2echeck…@booknook.test`) or publishing test books (titles like "Prodcheck …", "E2E Deployment Check …", "Flowcheck …"). The deployed app is production with a real user base, and such entries surface to the user as unwanted bot activity. Verify deployments with **read-only requests only** (`GET /api/books/latest` against the deployed backend is sufficient), and exercise any writes only against a local dev server with local data.

## Stack quirks

- Next.js 16 (App Router) + React 19 with `reactCompiler: true` in `next.config.ts` — don't add manual `useMemo`/`useCallback` memoization.
- `cacheComponents: true` and `partialPrefetching: true` are enabled — async components need `Suspense` boundaries / the new caching model, not the pre-16 defaults (check `node_modules/next/dist/docs/`). `new Date()` (or any non-deterministic value) breaks static prerender even inside client components — defer it to `useEffect` (see `src/components/layout/FooterYear.tsx`). URL-read client hooks (`usePathname`, `useParams`) must sit inside a `Suspense` boundary on dynamic routes — the Navbar is wrapped in one in `layout.tsx`, and `src/app/books/[title]/page.tsx` is a server component that awaits `params` and passes values as props to a client component.
- Tailwind CSS v4 via `@tailwindcss/turbopack` — no `tailwind.config.js`; theme lives in `@theme inline` in `src/app/globals.css`.
- The hero `Banner` uses Swiper 14 (`swiper/react` + `swiper/css*` imports inside the client component, Swiper overrides appended to `globals.css`, `Suspense`-wrapped as `BannerFallback` in `page.tsx`): Swiper module constructors run `new Date()` during render, which `cacheComponents` rejects outside a Suspense/streamed boundary. Pagination dot styling must target `.banner .swiper-pagination-*` in `globals.css`.
- `src/proxy.ts` (Next.js 16's middleware-replacement convention) runs on the Next.js server and does two things: (1) it is the **API proxy** — the browser calls only same-origin `/api/library/*` paths (base URL in `src/lib/backend.ts`), which the proxy rewrites to the standalone Express backend via the backend-only `LIBRARY_API_URL` env var; the backend's URL has no existence in client code (`NEXT_PUBLIC_API_URL` is gone — rename it to `LIBRARY_API_URL` in Vercel's server env if pulling fresh), and (2) it gates the private routes (`/books/:title`, `/my-books`, `/my-borrows`, `/my-profile`, `/add-book`) by checking the Better Auth session cookie and redirecting to `/login?next=…` (the login page folds `?next=` into the `booknook-next` sessionStorage key). `/books` itself stays public. Keep `RequireAuth` on private pages as the client-side second layer.
- With `cacheComponents`, route segment configs like `export const dynamic = "force-dynamic"` are build errors — Route Handlers are dynamic by default automatically (they run per-request when they touch network/DB). Client-side data fetching (e.g. `LatestBooks`) keeps the page a static shell with a mounted skeleton.
- shadcn/ui (`components.json`, style `base-nova`) built on `@base-ui/react` — ~80 pre-installed primitives in `src/components/ui/`. Use these before writing custom UI. Path alias `@/*` → `src/*`.

## Conventions

- Loading UI: shared `LoadingSection`/`Spinner` from `src/components/ui/LoadingSpinner.tsx` (emerald spinning ring, `role="status"`) replaced every text "Loading…" — used by `RequireAuth`, My Books, My Borrows, `/books/[title]` resolve, My Profile; LatestBooks keeps its skeleton grid.
- Tab titles: `PageTitle` client component (`src/components/layout/PageTitle.tsx`) renders `<PageTitle title="BookNook | <Route>" />` in every page (details use the book title, e.g. "BookNook | The Hobbit"); client pages can't export Next `metadata`, so titles are set via `document.title` with reset on unmount. On `/books/[title]` the URL param goes through `safeDecode` (`decodeURIComponent`) before matching/lookup/synthesizing, so `%20`/`%2C` never leaks into a displayed book name; `decodeTitle()` in `src/lib/books.ts` is applied at every render point of a book name (All Books list, Homepage cards, My Books, My Borrows rows + their hrefs, details' safeDecode) — book names must never display URL encoding.
- Custom 404: `src/app/not-found.tsx` — dark-green card (BookX icon, "404 / Page not found"), "Back to Home" primary + "Browse Books" secondary; never matches a real book (details page never 404s apart from the global catch-all).
- Toasts: `ToastPopup` (`src/components/ui/toast-popup.tsx`, with a re-export shim at `src/components/ui/toast.tsx` — the original unused shadcn toast module was replaced) — fixed bottom-right dark panel, icon circle, slide-in/fade, X close, 4.2s auto-dismiss. Register page: failed validation (including the password policy) pops a red "Registration unsuccessful" toast and/or an inline password error; success shows a green toast, signs the fresh session out, then redirects after ~1.1s to `/login`. Login page: title "Login", Email + Password + **Forgot Password?** link (pops a green "Password reset link sent" toast) + Login button; failures pop red "Login unsuccessful" toasts; success navigates to `booknook-next` or `/`; Google button and Register link unchanged.

- Responsive by default at three breakpoints — mobile (default single-column stacks), `sm/md` tablet (2-col grids, `max-w` cards), `lg` desktop (3-col sections). Book grids: `grid-cols-2 sm:grid-cols-3` (3 cards per row on desktop — spec); My Books / My Borrows rows stack image+info above full-width actions on mobile (`sm:flex-row` with `sm:shrink-0` button group); navbar uses the hamburger menu below `md` unless logged in. Book titles never truncate to one line — cards and rows use `line-clamp-2` so full names stay visible on every page.

- Design language: dark emerald-green homepage (`Banner` with exactly **3 Sliper slides, each backed by a library/books Unsplash photo — never a plain black slide** → `LatestBooks` at `#0d2318` → "How Borrowing Works" at `#11291b` → "Top Categories" at `#0a1d12`, cards `border-white/10 bg-white/5`), slate/emerald accents, `lucide-react` icons — match `page.tsx` and `Navbar.tsx`. Homepage has no stats bar, no reviews/FAQ sections.
- New routes go in `src/app/<route>/page.tsx`; add nav links to the `navLinks` array in `Navbar.tsx`.
- Data is mocked with module-level arrays (e.g., `sampleBooks` in `page.tsx`) — follow that pattern until a backend exists.
