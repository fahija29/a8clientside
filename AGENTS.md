# AGENTS.md

## Project

**BookNook** (`cat_ron`) — small online library app (discover, add, borrow, return books). Frontend + two API routes. Routes: home `/`, books list `/books`, book details `/books/[title]`, `/login`, `/register` (mock auth via localStorage); private (gated by `RequireAuth`, visible in navbar only when logged in): `/add-book`, `/my-books`, `/my-borrows`, `/my-profile` (accessed via the navbar avatar dropdown showing the user's **name, My Profile + Logout**; the profile card shows large circular avatar, serif name, email, "Member since" from `AuthUser.joinedAt` resolved per-account by email via a `booknook-members` registry in localStorage — stamped by `registerMember()` at **registration** (or first login for non-registered users) and permanent thereafter; an **Edit Profile** in-card form edits name + photo (≤1MB Data URL) via `AuthProvider.updateUser` — email is the identity and stays read-only); `logout()` clears the session **and always routes to `/`** (home) from any page — via `window.location.replace("/")` (full page load) so a private page's `RequireAuth` gate can never race the navigation and flash the login page; API `/api/books/latest` (MongoDB `find().sort({ addedAt: -1 }).limit(?limit, default 10)` via `src/lib/mongo.ts` + `MONGODB_URI` in `.env.local`; falls back to the mock catalog when no MongoDB is reachable; **seeds the mock catalog on an empty collection only when `BOOKNOOK_SEED=1`** — opt-in for local demos, deliberately never set on Vercel so the deployment never auto-adds rows) and `/api/books/detail?title=` (case-insensitive single-title lookup in the same collection). Homepage "New Arrivals" shows the latest **10** books (2 rows × 5 on desktop; `grid-cols-2` mobile, `sm:grid-cols-3` tablet — owner preference overrides the spec's 6/3-col) fetched client-side (`src/components/home/LatestBooks.tsx`, `/api/books/latest?limit=10`); `/books` lists all 20 + user-added books from `src/lib/userBooks.ts`; borrows from `src/lib/borrows.ts`. The details page borrows through a modal (`Borrow "Title"` + read-only User Name/User Email inputs prefilled from the auth session, Confirm Borrow) — identity fields are never editable. `Book` carries details-page fields — `description`, `addedBy {name, email}`, `copies` (optional). The Add Book form (dark-green hero "Add a Book" + centered `#0a1d12` form section, matching the reference) captures Book Title/Author Name (2-col), Category + Total Copies (2-col), a **file-upload cover picker** (image ≤1MB read as Data URL, otherwise `FALLBACK_COVER`), Short Description, and read-only User Name/User Email prefilled from the session (stored as `addedBy` in localStorage), with a full-width "Add Book" button; details without a description get a synthesized per-book fallback; `FALLBACK_COVER` (exported from `src/lib/books.ts`) is applied via `onError` when covers 404. **The details page never renders a 404**: it resolves via local catalog → `/api/books/detail` → a synthesized per-title `Book` (FALLBACK_COVER, composed description, donor = signed-in user) — `notFound()` is not used on `/books/[title]`. Availability = `copies − active borrows of that title` (from `getUserBorrows()`); when `copiesLeft` reaches 0 the button shows "Not Available" (disabled, muted-green combinated, line-through) **for everyone including the borrower** — "Borrowed — yours for 7 days" shows only while the holder still has copies remaining. Register success **keeps the just-started session** (owner override of the spec's register→Login step) and after ~1.1s navigates to the remembered `booknook-next` destination (e.g. the book details they tapped from) or `/` — **exactly the same behavior as login** (reads then clears the key).

## Git policy — only the owner commits

- **Agents must never run `git commit`/`git push`** in this repo: leave all changes uncommitted for the owner (fahija29) to review and commit from their own terminal.
- Enforced by the tracked hooks `.githooks/pre-commit` + `.githooks/pre-push` (POSIX sh): they refuse the operation when an AI/agent session is detected via env vars (`OPENCODE*`, `AI_AGENT`, `AGENT`, `CLAUDECODE`, `CURSOR_AGENT`, `COPILOT_AGENT`, `WINDSURF_AGENT`, `AIDER_MODEL`, `REPLIT_AGENT`, …). Owner terminals have none of those set and pass (exit 0).
- The hooks are wired with `core.hooksPath=.githooks` (local config — `npm run setup:hooks` restores it on a fresh clone). Local hooks can be bypassed with `--no-verify`; GitHub-side enforcement is the owner's branch ruleset (owner-only pushes) plus disabling the Copilot coding agent and revoking unknown OAuth apps/deploy keys.

There are no tests and no CI. Verify changes with `npm run build` and `npm run lint`.

## STRICT RULE — no test writes to production

Do **not** verify deployments or test features against the deployed app by creating throwaway accounts (e.g. `prodtest…@booknook.test`, `e2echeck…@booknook.test`) or publishing test books (titles like "Prodcheck …", "E2E Deployment Check …", "Flowcheck …"). The deployed app is production with a real user base, and such entries surface to the user as unwanted bot activity. Verify deployments with **read-only requests only** (`GET /api/books/latest` against the deployed backend is sufficient), and exercise any writes only against a local dev server with local data.

## Stack quirks

- Next.js 16 (App Router) + React 19 with `reactCompiler: true` in `next.config.ts` — don't add manual `useMemo`/`useCallback` memoization.
- `cacheComponents: true` and `partialPrefetching: true` are enabled — async components need `Suspense` boundaries / the new caching model, not the pre-16 defaults (check `node_modules/next/dist/docs/`). `new Date()` (or any non-deterministic value) breaks static prerender even inside client components — defer it to `useEffect` (see `src/components/layout/FooterYear.tsx`). URL-read client hooks (`usePathname`, `useParams`) must sit inside a `Suspense` boundary on dynamic routes — the Navbar is wrapped in one in `layout.tsx`, and `src/app/books/[title]/page.tsx` is a server component that awaits `params` and passes values as props to a client component.
- Tailwind CSS v4 via `@tailwindcss/turbopack` — no `tailwind.config.js`; theme lives in `@theme inline` in `src/app/globals.css`.
- The hero `Banner` uses Swiper 14 (`swiper/react` + `swiper/css*` imports inside the client component, Swiper overrides appended to `globals.css`, `Suspense`-wrapped as `BannerFallback` in `page.tsx`): Swiper module constructors run `new Date()` during render, which `cacheComponents` rejects outside a Suspense/streamed boundary. Pagination dot styling must target `.banner .swiper-pagination-*` in `globals.css`. `BannerFallback` (the SSR shell) renders a **static replica of slide 1 including its real cover tiles** (`slides[0]` + `CollageFan`), so the browser downloads the 7 visible covers at HTML parse time — before Swiper hydrates — and the hydrated slider swaps in identical markup from cache with no loading gap. Note: manually rendered `<link rel="preload" as="image">`/`preconnect` hints are **dropped by React 19** (deduped against same-`src` `<img>` tags), so shell `<img>` tiles are the only reliable way to front-run cover fetches; React auto-preloads later slides' covers itself. Keep the replica in sync with `slides[0]`.
- `src/proxy.ts` (Next.js 16's middleware-replacement convention) runs on the Next.js server and does two things: (1) it is the **API proxy** — the browser calls only same-origin `/api/library/*` paths (base URL in `src/lib/backend.ts`), which the proxy rewrites to the standalone Express backend via the backend-only `LIBRARY_API_URL` env var; the backend's URL has no existence in client code (`NEXT_PUBLIC_API_URL` is gone — rename it to `LIBRARY_API_URL` in Vercel's server env if pulling fresh), and (2) it gates the private routes (`/books/:title`, `/my-books`, `/my-borrows`, `/my-profile`, `/add-book`) by checking the Better Auth session cookie: the **book details route** redirects signed-out visitors to `/please-login?next=…` — an interstitial page ("Please login first", lock icon) with **Login** and **Register** buttons plus a "Continue browsing all books" link; it stashes `next` into the `booknook-next` sessionStorage key on mount (both buttons then return the reader to the intended book — Login reads the key after sign-in, Register hands off to `/login` with the key intact) and auto-forwards already-signed-in visitors to the destination. The **other private routes** redirect straight to `/login?next=…` (the login page folds `?next=` into the same `booknook-next` key). `/books` itself stays public. The proxy also **blocks unauthenticated writes at the API boundary**: any non-GET/HEAD/OPTIONS request to `/api/library/*` without a session cookie gets an immediate `401 {"success":false,"message":"Authentication required"}` from the proxy itself and never reaches the Express backend — this is what stops deployment-checker/AI bots from adding books (the backend's JWT check remains the second layer). The `isBotCheckBook` filter in `src/lib/books.ts` (used by `fetchAllBooks`, `/api/books/latest`, `/api/books/detail`) stays: it hides the historical bot probe books ("Prodcheck <ms>", "E2E Deployment Check <ms>") already sitting in the production database. Keep `RequireAuth` on private pages as the client-side second layer.
- With `cacheComponents`, route segment configs like `export const dynamic = "force-dynamic"` are build errors — Route Handlers are dynamic by default automatically (they run per-request when they touch network/DB). Client-side data fetching (e.g. `LatestBooks`) keeps the page a static shell with a mounted skeleton.
- shadcn/ui (`components.json`, style `base-nova`) built on `@base-ui/react` — ~80 pre-installed primitives in `src/components/ui/`. Use these before writing custom UI. Path alias `@/*` → `src/*`.

## Conventions

- Loading UI: shared `LoadingSection`/`Spinner` from `src/components/ui/LoadingSpinner.tsx` (emerald spinning ring, `role="status"`) replaced every text "Loading…" — used by `RequireAuth`, My Books, My Borrows, `/books/[title]` resolve, My Profile; LatestBooks keeps its skeleton grid.
- Tab titles: `PageTitle` client component (`src/components/layout/PageTitle.tsx`) renders `<PageTitle title="BookNook | <Route>" />` in every page (details use the book title, e.g. "BookNook | The Hobbit"); client pages can't export Next `metadata`, so titles are set via `document.title` with reset on unmount. On `/books/[title]` the URL param goes through `safeDecode` (`decodeURIComponent`) before matching/lookup/synthesizing, so `%20`/`%2C` never leaks into a displayed book name; `decodeTitle()` in `src/lib/books.ts` is applied at every render point of a book name (All Books list, Homepage cards, My Books, My Borrows rows + their hrefs, details' safeDecode) — book names must never display URL encoding.
- Custom 404: `src/app/not-found.tsx` — dark-green card (BookX icon, "404 / Page not found"), "Back to Home" primary + "Browse Books" secondary; never matches a real book (details page never 404s apart from the global catch-all).
- Toasts: `ToastPopup` (`src/components/ui/toast-popup.tsx`, with a re-export shim at `src/components/ui/toast.tsx` — the original unused shadcn toast module was replaced) — fixed bottom-right dark panel, icon circle, slide-in/fade, X close, 4.2s auto-dismiss. Register page: failed validation (including the password policy) pops a red "Registration unsuccessful" toast and/or an inline password error; success shows a green toast, keeps the fresh session, then after ~1.1s navigates to the remembered `booknook-next` destination or `/` (same as login). Login page: title "Login", Email + Password + **Forgot Password?** link (pops a green "Password reset link sent" toast) + Login button; failures pop red "Login unsuccessful" toasts; success navigates to `booknook-next` or `/`; Google button and Register link unchanged.

- Responsive by default at three breakpoints — mobile (default single-column stacks), `sm/md` tablet (2-col grids, `max-w` cards), `lg` desktop (3-col sections). Book grids: `grid-cols-2 sm:grid-cols-3 lg:grid-cols-5` (5 cards per row on desktop — **owner preference, overrides the spec's 3-per-row**; New Arrivals loads 10 so the 5-col grid fills 2 clean rows); My Books / My Borrows rows stack image+info above full-width actions on mobile (`sm:flex-row` with `sm:shrink-0` button group); navbar uses the hamburger menu below `md` unless logged in. Book titles never truncate to one line — cards and rows use `line-clamp-2` so full names stay visible on every page.

- Design language: dark emerald-green homepage (`Banner` with exactly **3 Sliper slides, each backed by a library/books Unsplash photo — never a plain black slide** → `LatestBooks` at `#0d2318` → "How Borrowing Works" at `#11291b` → "Top Categories" at `#0a1d12`, cards `border-white/10 bg-white/5`), slate/emerald accents, `lucide-react` icons — match `page.tsx` and `Navbar.tsx`. Homepage has no stats bar, no reviews/FAQ sections. Footer social icons (Facebook, Instagram, X, etc.) are **decorative only — owner said they're "for show"**: don't wire them to real URLs or expect navigation.
- New routes go in `src/app/<route>/page.tsx`; add nav links to the `navLinks` array in `Navbar.tsx`.
- Data is mocked with module-level arrays (e.g., `sampleBooks` in `page.tsx`) — follow that pattern until a backend exists.
